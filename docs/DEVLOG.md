# CPPG 기출 마스터 — 개발 기록

> 개인정보관리사(CPPG) 문제집 PDF로 기출을 풀어 보는 웹 서비스
> 사이트: https://cppg.songcoco.kr · 저장소: https://github.com/lshysh626/cppg-quiz
> 개발 기간: 2026-10-15 (1일) · Claude Code와 페어 프로그래밍

## 1. 한 줄 요약

저작권이 있는 유료 문제집 PDF를 **서버 없이 브라우저 안에서 파싱**해 문제은행으로 만들고,
**비밀번호로 암호화한 파일**을 공개 저장소에 올려 PC·모바일 어디서나 같은 자료로 공부할 수 있게 했다.

## 2. 배경과 목표

- 시중 CPPG 문제집(컴공로드맵 실전 300제, 3회차 × 100문항, 정답·해설 포함)을 PDF로 구매했다.
- 종이 대신 웹에서 회차별·과목별로 풀고, 채점하고, 틀린 문제를 모아 다시 풀고 싶었다.
- 이전에 만든 정보보안기사 실기 풀이 사이트(IS MASTER, `gichul-study`)의 화면과 사용 흐름을 그대로 이어 가고 싶었다.

**제약 조건**

| 제약 | 내용 |
| --- | --- |
| 저작권 | 문제집은 유료 자료다. 페이지마다 저작권 표기와 구매자 이메일 워터마크가 있다. 문제 데이터를 공개 저장소나 사이트에 평문으로 올리면 안 된다. |
| 비용 | 서버·DB 없이 무료 정적 호스팅(GitHub Pages)만 쓴다. |
| 다중 기기 | PC와 폰에서 같은 자료를 써야 한다. |

## 3. 결과물

- **세 가지 풀이 모드**: 즉시 채점 / 실전 모드(다 풀고 일괄 채점) / 학습 모드(정답·해설 먼저 보기)
- **실전 모의고사**: 300문항에서 실제 시험 과목 비율(10·20·25·30·15)대로 100문항 무작위 출제, 120분 타이머, 과목별 40%·총점 60% 기준 과락·합격 판정
- 회차별·과목별 풀기, 문항표(OMR) 패널, 풀던 문제 이어 풀기
- **다시 볼 문제**: 폴더·하위 폴더 북마크, 여러 폴더를 골라 섞어 풀기, 틀린 문제 자동 수집
- **원본 보기**: 표·그림이 이미지로 들어간 문제는 저장된 PDF 페이지를 캔버스로 바로 렌더링 (휠 확대, 드래그 이동)
- 채점 결과(과목별·문항별), 학습 통계, 기록 내보내기/가져오기
- 키보드 단축키, 반응형(모바일 ~ 2560px 모니터)

## 4. 아키텍처

```
[구매한 PDF] ──(브라우저 안에서만)──▶ PDF.js 파싱 ──▶ 문제 300개(JSON) ──▶ IndexedDB
      │
      └─ 설정에서 비밀번호로 암호화 ──▶ library/cppg.enc ──▶ GitHub Pages
                                                         │
               [다른 PC·폰] 비밀번호 입력 ◀──────────────┘
                     └─▶ Web Crypto로 복호화 ─▶ PDF.js 파싱 ─▶ IndexedDB (또는 탭 메모리만)
```

| 파일 | 역할 |
| --- | --- |
| `js/parser.js` | PDF → 문제 데이터. 회차 표지·정답표 위치로 구간을 나누고 문항·선지·정답·해설을 추출 |
| `js/vault.js` | AES-256-GCM + PBKDF2-SHA256(150만 회) 암호화/복호화 |
| `js/db.js` | IndexedDB 키-값 저장소 (PDF 원본, 문제 데이터) |
| `js/app.js` | 해시 라우팅 SPA: 대시보드, 기출 풀기, 풀이·채점, 폴더, 통계, 설정, 라이트박스 |
| `style.css` | IS MASTER 다크 네이비 테마, rem 기반 반응형 |
| `vendor/pdfjs/` | PDF.js 3.4.120 자체 호스팅 |

프레임워크와 빌드 단계 없이 순수 HTML/CSS/JS로 만들었다. 정적 파일 그대로 배포된다.

## 5. 기술적으로 어려웠던 점과 해결

### 5-1. PDF 텍스트의 띄어쓰기 복원

문제집 본문은 줄 단위로 끊겨 있다. 줄바꿈 자리가 **띄어쓰기**였는지 **단어 중간**이었는지 알아야
"설명으로 틀린"과 "의미하므로"를 각각 올바르게 이을 수 있다.

1. 처음에는 Python(pypdf)으로 파싱했다. pypdf는 원문 줄 끝 공백을 남겨 줘서, "줄 끝에 공백이 없고 앞뒤가 한글이면 붙인다"는 규칙으로 300문항을 정확히 뽑았다.
2. 브라우저용으로 옮기면서 PDF.js `getTextContent()`를 쓰자, PDF.js가 **줄 끝 공백을 지워** 판단 근거가 사라졌다. `disableCombineTextItems` 옵션은 문단을 통째로 주지만 일부 줄바꿈에서는 공백을 놓쳤다("민감정보로판단하여").
3. 그래서 **그리기 명령(operator list)** 을 직접 읽었다. `showText`의 글리프와 `moveText`·`setTextMatrix`의 줄 이동을 추적해 pypdf와 같은 방식으로 줄 텍스트를 재구성했다. 원문 공백 글리프가 그대로 남아 있어 문제가 풀렸다.
4. **검증**: 앞서 만든 Python 결과 300문항을 기준 데이터로 두고 브라우저 파서 결과와 필드별로 비교했다. 정답·본문·페이지가 모두 일치했고, 남은 차이는 `㈜`↔`(주)` 같은 표기뿐이었다.

그 밖의 처리:
- 보기 기호 `ᄀ·ᄂ`(첫소리 자모 U+1100대) → 일반 자모 `ㄱ·ㄴ`으로 정규화
- 이전 선지 끝에 다음 문항 번호가 붙어 나오는 경우("…유형46  다음 중") 분리
- 페이지 번호·저작권 표기·워터마크 이메일 줄 제거
- 표가 이미지로 들어간 문제는 텍스트로 복원하지 않고 **원본 페이지 렌더링**으로 해결

### 5-2. 저작권 자료를 공개 저장소에서 다루기

| 단계 | 방식 | 이유 |
| --- | --- | --- |
| 1 | PDF·생성 데이터 `.gitignore`, 코드만 공개 | 평문 배포 방지 |
| 2 | 사용자가 PDF를 고르면 브라우저 안에서만 파싱해 IndexedDB에 저장 | 서버 업로드 없음 |
| 3 | PDF를 비밀번호로 암호화한 `cppg.enc`만 저장소에 올림 | 다중 기기 지원 + 암호문만 공개 |

- 암호화: Web Crypto API, AES-256-GCM, PBKDF2-SHA256 150만 회, 무작위 salt/IV, 헤더를 인증 데이터(AAD)로 묶음
- 서버가 없어 시도 횟수 제한을 걸 수 없다. 그래서 키 유도 비용을 높이고 15자 이상 문장형 비밀번호를 강제했다.
- 올리기 전에 결과 파일에서 PDF 헤더와 워터마크 이메일이 검출되지 않는지, 엔트로피가 8.0 bits/byte인지 확인했다.
- 공용 PC용 "이 기기에 저장하지 않기" 옵션: 복호화한 자료를 탭 메모리에만 둔다.

### 5-3. 보안 강화

- **CSP**: `script-src 'self'`로 사이트 자체 스크립트만 실행. 외부 요청은 Google Fonts만 허용
- **공급망**: PDF.js를 CDN 대신 저장소에 포함 (cdnjs 배포본과 SHA-256 일치 확인)
- PDF.js `isEvalSupported: false`, `referrer` 미전송
- 모든 동적 텍스트를 HTML 이스케이프. 폴더 이름에 공격 코드를 심은 기록 파일을 가져와도 실행되지 않는지 테스트

### 5-4. 배포와 도메인

- GitHub Pages(정적, `.nojekyll`) → 커스텀 도메인 `cppg.songcoco.kr` (가비아 DNS에 CNAME 레코드)
- HTTPS 인증서 발급이 멈춰 있어, Pages 도메인 설정을 해제했다가 다시 등록해 발급을 다시 요청 → 발급 후 HTTPS 강제 적용
- 기존 `lshysh626.github.io/cppg-quiz` 주소는 새 도메인으로 301 리다이렉트

## 6. 테스트

Playwright로 실제 브라우저(Edge)를 띄워 시나리오 테스트를 돌렸다.

- PDF 불러오기(약 8초) → 새로고침 후 유지 → 즉시 채점 → 원본 보기 → 폴더 저장 → 이어 풀기
- 실전 모드 100문항 입력·제출 → 75점이어도 한 과목이 0점이면 **과락 불합격** 판정 확인
- 암호화 파일 생성 → 다른 기기를 흉내 낸 새 브라우저 컨텍스트에서 틀린 비밀번호 거부, 올바른 비밀번호로 열기, 임시 모드에서 새로고침 시 데이터 소멸 확인
- 모바일(390px)과 1366·1920·2560px 화면 캡처, 가로 스크롤 없음, 콘솔 오류 0건

테스트 중 찾아 고친 버그:
- 문항표 패널이 상단 바의 나가기 버튼을 가림
- PDF가 없을 때 메뉴를 누르면 말없이 대시보드로 돌아가 "이동이 안 되는" 것처럼 보임
- 큰 모니터에서 콘텐츠가 왼쪽 위에 몰림 → 가운데 정렬 + 화면 폭에 비례한 글자 크기
- 모바일에서 문항표 탭이 선지를 가림 → 떠 있는 버튼으로 변경

## 8. 배운 점

- **기준 데이터로 검증하기**: 파서를 다른 라이브러리로 옮길 때, 먼저 만든 결과를 정답지로 두고 필드별로 비교하니 띄어쓰기처럼 눈으로는 놓치기 쉬운 회귀를 바로 잡을 수 있었다.
- **라이브러리 추상화 아래로 내려가기**: 고수준 API(`getTextContent`)가 정보를 버릴 때는 한 단계 아래(operator list)에 원하는 데이터가 남아 있는 경우가 있다.
- **서버 없는 접근 제어의 한계**: 시도 횟수 제한이 없으니 보안이 비밀번호 강도와 키 유도 비용에 달려 있다. 이 점을 사용자 안내와 입력 검증에 반영했다.
